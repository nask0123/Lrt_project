# Astana LRT

Независимый full-stack прототип: интерактивная карта OpenStreetMap, 15 виртуальных составов на линии и 4 в резерве, 18 станций с опубликованными названиями и проектными координатами, профиль и виртуальный счёт.

## Возможности

- Карта Астаны с 18 станциями, движением 15 поездов и выбором состава.
- Планирование маршрута, прогноз прибытия и напоминание о выходе на открытой странице.
- Геопозиция по запросу и поиск ближайшей станции.
- Мобильная нижняя панель и разделы «Карта», «Билеты», «Профиль».
- Демо-счёт, покупка QR-билета, история билетов и загрузка аватарки.
- Два сценария движения и сгенерированная загрузка четырёх вагонов.

> Это учебный проект: позиции поездов, загрузка и билеты демонстрационные. Приложение не связано с оператором LRT.

## Запуск
Дважды нажмите START.cmd в этой папке, затем откройте http://127.0.0.1:5173. Окно оставьте открытым. Лаунчер ищет Node.js в PATH, Program Files и установленной среде Codex; fnm и npm не требуются. Если Node.js не найден, установите Windows Installer (.msi), LTS с https://nodejs.org/en/download. Нужен Node.js 22+; установка пакетов не требуется.

```powershell
git clone https://github.com/nask0123/Lrt_project.git
cd Lrt_project
node server.mjs
```
Открыть http://127.0.0.1:5173. PORT задаёт другой порт.

## Проверка и сборка
```powershell
node --test tests/*.test.mjs
node build.mjs
```

frontend/ — HTML, CSS, JS. lib/transit.mjs — детерминированная серверная симуляция. lib/api.mjs — API. server.mjs — локальный Node HTTP-сервер. build.mjs собирает тот же код в автономный Cloudflare Worker dist/server/index.js. Настройка и публикация Worker выполняются отдельно; для локального запуска сборка не нужна. GitHub Pages не запускает этот Node.js-бэкенд.

GET /api/transit?scenario=interval|classic — снимок позиций, состава парка, загрузки 4 вагонов каждого поезда и шести ближайших прибытий на каждую станцию. GET /api/profile — демо-профиль. POST /api/profile {name}; POST /api/topup {amount:500|1000|2000}; POST /api/ticket {} — условная поездка за 200 ₸.

По умолчанию scenario=interval: 15 поездов, интервал в каждом направлении 330 секунд (5:30), оборот 4950 секунд (82:30), переезды ~104–138 секунд. Альтернативный scenario=classic сохраняет 180–240 секунд между станциями; при тех же 15 поездах интервал ~8:49. Стоянки 25 секунд, разворот на конечных; обновление каждую секунду. Время в одну сторону включает стоянку на начальной станции, но не на конечной. Время сервера общее для клиентов. Нет ускорения скрытой вкладки. При потере связи интерфейс показывает ошибку и переподключается.

Профиль и 8 последних операций хранятся в HttpOnly cookie браузера 30 дней. Это намеренно демонстрационная модель без аутентификации, БД и платежей. Cookie не подписана; не использовать этот баланс для реальных денег. Параллельные вкладки могут перезаписать демо-состояние. Для production нужны авторизация, БД, атомарные транзакции, идемпотентность платежей и настоящий транспортный feed.

## Данные
Открытый документированный API GPS-позиций именно LRT не найден при поиске 6 ноября 2026. Найденный https://data.egov.kz/datasets/view?index=avtobustardyn_osy_uakyttagy_ko относится к автобусам. Оператор: https://cts.gov.kz/ru/ . Неофициальное приложение. Геометрия линии упрощена; загрузка и тариф демонстрационные. Не использовать для реальной навигации. При получении API заменить источник snapshot в lib/api.mjs, сохранив формат ответа.

Google Fonts необязателен: при отсутствии сети используется Arial. Leaflet 1.9.4 поставляется локально в frontend/vendor, лицензия приложена. Подложка OpenStreetMap загружается по HTTPS с tile.openstreetmap.org и требует интернета. Нет загрузки тайлов заранее или офлайн-кэша; стандартная атрибуция видима. При сбое тайлов появляется сообщение, слой станций и поездов остаётся доступен.


## Параметры парка и источники
19 составов: 15 в работе, 4 в резерве. По 4 вагона, до 650 пассажиров на поезд, 60 вагонов на линии, 76 во всём парке. Источник: Kazinform, 24 апреля 2026, со ссылкой на CTS: https://www.inform.kz/ru/odin-sostav-lrt-v-astane-smozhet-perevozit-do-650-passazhirov-6e5675 . Статья описывает плановый режим, не текущий GPS-feed. Указанный там интервал 5–10 минут; 5–6 минут — целевой сценарий пользователя. Для равномерного интервала 5:30 при 15 поездах используем оборот 15 × 330 = 4950 секунд. Пассажиры сгенерированы на сервере и меняются на станциях, сумма по четырём вагонам совпадает с общим числом и не превышает вместимость. Резервные поезда не имеют координат и не отображаются как движущиеся.

## Географическая карта и мобильная версия
Координаты: https://hearings.ndbecology.gov.kz/Public/PubHearings/PublicHearingDetail?hearingId=31862 . Имена станций: https://www.inform.kz/ru/opublikovana-shema-stantsiy-lrt-v-astane-aab321b1 . В документе координаты 106 и 107 совпадают, поэтому 107 оценена между соседними станциями и помечена estimated. Линия — упрощённые отрезки между станциями, а не геодезическая съёмка рельсов. Сервер рассчитывает lat/lng поездов вдоль этих отрезков. На карте: перетаскивание, pinch-to-zoom, кнопки масштаба, вся линия, выбор и слежение за поездом. Колесо мыши не перехватывается.
Мобильный макет проверен в браузере при 390×844 и 320×740: карта на весь основной экран, раскрывающаяся нижняя панель, навигация Карта / Билеты / Профиль, кнопки масштаба 44×44, горизонтальной прокрутки нет. Это проверка размеров в браузере, не тест на физическом телефоне.

## QR-билет и аватарка
После POST /api/ticket сервер создаёт latestTicket {id, issuedAt, amount}; он сохраняется вместе с демо-профилем в cookie. Покупка открывает QR-код; кнопка «Мой QR-билет» повторно показывает последний билет без нового списания. Содержимое QR: DEMO:ASTANA-LRT:<UUID>. QR генерируется локальной библиотекой qrcode-generator 1.4.4 (MIT), без стороннего сервиса. Билет не подходит для реального проезда.
Аватарка: JPG, PNG, WebP до 5 МБ. Браузер обрезает изображение по центру до 256×256 и сохраняет JPEG в localStorage только этого origin. В серверную cookie фото не помещается и на сервер не передаётся; между устройствами не синхронизируется. Доступно удаление фото. Ошибки формата, чтения и переполнения хранилища показываются в профиле.
Проверено: создание/сохранение билета, уникальные номера, отказ при недостаточном балансе, размер cookie; покупка, повторное открытие QR и загрузка/сохранение/удаление аватарки в браузере.

## Планирование поездки и геопозиция
GET /api/journey?from=101&to=118&scenario=interval рассчитывает ближайшее отправление в нужную сторону, промежуточные стоянки и прибытие. Все пары станций проверяются тестами в обоих сценариях. Маршрут выделяется на карте. Напоминание о выходе работает только на открытой странице по времени симуляции; это не push и не отслеживание реальной поездки. Карточка поезда подсказывает менее загруженный вагон по демо-данным.
Кнопка «Где я» делает разовый запрос геопозиции с разрешением пользователя (HTTPS или localhost). Ближайшая станция определяется в браузере по расстоянию по прямой. Координаты не сохраняются и не отправляются в API проекта; картографический сервис получает обычные запросы тайлов отображаемой области. При отказе, таймауте или отсутствии геопозиции доступен ручной выбор станций. Реальное получение GPS в тестовой среде не подтвердилось: проверены таймаут и ручной выбор, расчёт расстояний — автоматическими тестами.
Раздел «Билеты» хранит до 50 QR-билетов в localStorage этого браузера, без синхронизации. Очистка данных браузера удаляет историю. При недоступности хранилища новые билеты видны только в текущей сессии.
Задачи на будущее не реализованы: настоящая регистрация, серверная синхронизация, платежи, API оператора, PWA и офлайн-режим.

## Структура проекта

```text
frontend/       Интерфейс, карта, профиль и локальные библиотеки
lib/            API, география станций и симуляция движения
tests/          Проверки маршрутов, поездов и демо-счёта
server.mjs      Локальный HTTP-сервер
build.mjs       Сборка автономного Worker
START.cmd       Запуск в Windows двойным щелчком
```
